# ADR 001：按文件缓存解析结果，保存可重建的本机统计索引

- 日期：2026-10-01
- 状态：Accepted

## 背景

仪表盘原来用整个资料库的文件签名缓存全部记录。任何一个日志追加内容，就会重新打开所有历史 JSONL。真实资料库约 2,000 个文件、4.54 GiB；持续记录用量时，请求耗时 13–16 秒，主要耗在文件读取和解析。

## 选择

为仪表盘增加逐文件解析索引。未变化的文件复用解析结果；新文件、追加、截断、替换和修改重新解析对应文件。跨文件去重、镜像抑制和 token 计算继续由 `token_stats.py` 与 `codex_records.py` 完成，索引不另写统计规则。

使用 Python 标准库 SQLite 保存可重建的派生数据，减少重启后的全量读取。索引只保存事件身份、时间、模型、项目和 token 计数，不保存提示词、回复正文或工具输出。缓存位置与源码、会话目录分离；目录由程序创建，POSIX 下设为仅用户可访问。

文件签名包含设备、inode、大小、mtime 和 ctime；缓存内容附带校验和。解析源码指纹改变时自动丢弃旧索引。删除或归档后重新做全局去重，并移除已不存在的缓存条目。缓存不可用时明确告警，回退为内存缓存；原始会话始终只读。

## 备选项与取舍

- 只延长全量缓存时间：降低扫描频率，但活跃会话显示滞后，首次加载和重启仍然慢。
- 仅内存逐文件缓存：日常刷新快，但每次启动仍要读取全部历史。
- 文件尾增量解析：可以进一步优化巨大活跃文件，但需要持久化上下文、计数重置、未完成行等状态。当前选择重新解析发生变化的整个文件，先消除全资料库重读；保持现有解析语义更容易验证。
- 外部数据库/依赖：对单机可重建缓存没有额外收益，会增加安装步骤。

第一次建立索引仍需完整扫描；之后按文件更新。JSONL 是唯一统计来源，SQLite 不是账号账单或权威资料库，不涉及 Skill Center 的数据库迁移。
